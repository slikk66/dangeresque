## Implementation Detail

`src/summary.ts` exports four symbols:

- `bucketNameStatus(output: string): FileBuckets` — pure, parses
  `git diff --name-status` text. Excludes `.dangeresque/runs/` matches by
  evaluating the destination path (handles renames into runs/).
- `buildCanonicalLine(buckets: FileBuckets): string` — pure, formats the
  canonical `Files: ...` line; drops zero buckets; bare line when N=0.
- `rewriteSummaryFilesLine(content: string, canonicalLine: string)` —
  pure, locates the SUMMARY block via the same regex shape as
  `parseSummaryBlock` in `src/worktree.ts:321`, replaces the line matching
  `/^Files:.*$/m` scoped to inside the block. Returns `null` if SUMMARY
  block missing or has no Files: line. Preserves all other SUMMARY content.
- `normalizeSummaryFileCount({ worktreePath, archivePath, diffBase, builder })` —
  side-effecting shell that orchestrates: run git, parse, rewrite file,
  commit, update builder. Returns the canonical N on success or `null`
  on any failure.

Failure modes (each warn-and-degrade, never throw):

- git diff fails → `summary_normalize_failed` { reason: "git_diff_failed" }
- archive .md missing → `summary_normalize_failed` { reason: "archive_missing" }
- archive read fails → `summary_normalize_failed` { reason: "archive_read_failed" }
- SUMMARY block missing/no Files: line → `summary_normalize_failed` { reason: "summary_block_missing_or_malformed" }
- file write fails → `summary_normalize_failed` { reason: "archive_write_failed" }
- commit fails → `summary_normalize_failed` { reason: "commit_failed" }

On success, `setFilesChangedCount(N)` is called on the optional
`ArtifactBuilder` so the JSON's `files_changed_count` field stays in lockstep
with the .md's `Files:` line.

CLI integration at `src/cli.ts:532` is mode-agnostic — runs uniformly across
INVESTIGATE, IMPLEMENT, VERIFY, REFACTOR, TEST. The INVESTIGATE INVESTIGATE
artifact's reported `Files: 0 changed (read-only)` becomes `Files: 0 changed`
after normalization; the loss of the parenthetical descriptor is acceptable
per the INVESTIGATE-section-2 rationale.

No reviewer prompt change. No worker prompt change. Workers may continue to
self-report any shape — the CLI silently overrides between worker exit
and review dispatch.

## Risks / Uncertainty

- **Schema bump caveat.** Bumping `ARTIFACT_SCHEMA_VERSION` to `"3"`
  triggered `gatherArtifacts` to skip pre-existing v2 artifacts as
  "unsupported". The migration script reproduces the precedent set by
  commit `d997c83` (v1→v2) and brings all 70 historical artifacts up to
  v3 with `files_changed_count: 0` (correct default — the canonical
  count was not computed at the time those artifacts were written).
- **Migration is not part of the runtime CLI.** `scripts/migrate-artifacts-v3.mjs`
  is committed for traceability but not wired into `package.json` scripts.
  It was invoked once during this run via a temporary `yarn build` chain
  that was reverted before commit; the script is now a one-shot reference
  for the migration.
- **Field placement parity.** New artifacts have
  `files_changed_count` BEFORE `summary` (per the interface ordering at
  `artifact.ts:67`); migrated artifacts have it AT THE END (insertion
  order from `{...orig, schema_version: "3"}`). Cosmetic only —
  consumers read by name. If alignment matters later, a follow-up
  resave-via-builder migration would normalize.
- **Worker prompt template not touched.** The worker prompt at
  `config-templates/worker-prompt.md:72` still shows the example
  `Files: 2 changed (src/feature.ts, src/feature.test.ts)`. Workers will
  continue to write a hand-typed line; the CLI silently overrides. This

  templates (out of scope per the IMPLEMENT brief).
- **`src/index.ts` unchanged.** I considered re-exporting summary helpers
