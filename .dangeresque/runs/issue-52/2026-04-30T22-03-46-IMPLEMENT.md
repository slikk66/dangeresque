## Summary

Implemented per the staged IMPLEMENT direction in slikk66's comment on Issue #52. Replaced the shallow `{ ...DEFAULT_CONFIG, ...raw }` merge in `loadConfig` with a per-key merge:

- `allowedTools` and `disallowedTools` now concat the user's array onto the defaults and dedupe (preserve first-seen order: defaults first, user additions appended). Empty or missing user array leaves defaults intact.
- All other scalar/object fields keep last-wins behavior (current `{ ...DEFAULT_CONFIG, ...raw }` semantics).
- Unknown keys in user JSON pass through (object spread already handles this).
- Missing `config.json` still returns a defaults copy unchanged.

No changes to `init.ts`, no new template files, no CLI changes, no docs rewrite. Defaults remain the single source of truth in `src/config.ts`.

## Implementation Details

`src/config.ts:108-130` (loadConfig + mergeStringList):

```ts
export function loadConfig(projectRoot: string): DangeresqueConfig {
  const configPath = join(projectRoot, CONFIG_DIR, "config.json");
  if (!existsSync(configPath)) {
    return { ...DEFAULT_CONFIG };
  }
  const raw = JSON.parse(readFileSync(configPath, "utf-8"));
  const merged: DangeresqueConfig = { ...DEFAULT_CONFIG, ...raw };
  // Tool lists extend defaults rather than replace them: the user's config.json
  // is purely additions. Empty/missing user array leaves defaults untouched.
  merged.allowedTools = mergeStringList(DEFAULT_CONFIG.allowedTools, raw.allowedTools);
  merged.disallowedTools = mergeStringList(DEFAULT_CONFIG.disallowedTools, raw.disallowedTools);
  return merged;
}

function mergeStringList(defaults: string[], userValue: unknown): string[] {
  if (!Array.isArray(userValue) || userValue.length === 0) {
    return [...defaults];
  }
  const seen = new Set<string>();
  const merged: string[] = [];
  for (const v of [...defaults, ...userValue]) {
    if (typeof v !== "string" || seen.has(v)) continue;
    seen.add(v);
    merged.push(v);
  }
  return merged;
}
```

The two-line WHY comment explains a non-obvious invariant (extend, not replace) — matches CLAUDE.md guidance on when to comment.
